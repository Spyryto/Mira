# Studio IDE: CodeMirror pilot

A new IDE entry point is published at ide.html; the existing Workbench stays accessible and the two historical editions remain pinned. CodeMirror 6 is bundled locally, not loaded from a CDN. The checked Mira editor-services and snippet definitions compile to JS and PHP; the JS host owns editor transactions, DOM, browser storage, worker communication and compiler-report normalization. The compiler performs AST and type analysis in a worker. Revision IDs discard stale analysis. The current completion index is deliberately top-level only; on invalid source the last valid symbols are visibly stale. Native API catalog entries are inspectable, but are not presented as in-scope callable symbols. No local-block scope, receiver/type-driven completion, imports, tolerant parsing, annotations or complete HTML reference yet. Diagnostic spans come from the structured compiler error, without regex parsing; Unicode offset conventions need dedicated regression tests. The scanner is presentation-only. Curated snippets are syntax templates and do not claim inferred generic signatures. CI compiles both targets, checks editing in Chromium, captures phone and desktop screenshots and logs bundle size. Initial measured analysis timing appears in the status bar. No framework or LSP server.

Mobile navigation is a collapsible Workspace tree, not a hidden feature. Browser smoke tests record the initial analysis time and elapsed time from the beginning of typing a completion prefix to observing the popup, and capture both lexical and type diagnostics. These wall times include browser automation; they are not isolated compiler benchmarks.

The Inspector explicitly refreshes the provenance of a selected document symbol on each edit and analysis response; obsolete signatures cannot retain the verified label. This behavior is asserted after a lexical error in both browser viewports.

## Typed field completion

The first semantic field completion supports a top-level simple value assignment whose right side is a field chain. The compiler checks the complete preceding source on demand in the worker, so it can type a receiver even in a new document ending in incomplete `invoice ~`. A single cached promise per exact prefix avoids duplicate checks. The host decodes record schemas (including Named wrappers), preserves field type descriptions and normalizes a bounded tree to rows. Checked Mira code filters by receiver and prefix, excludes optional fields from direct access, and composes field tooltips. Nested required fields work; hover/signature can explain optional fields without recommending an invalid direct access. Unknown or invalid prefixes produce no suggestions. This is deliberately not a tolerant parser: local shadowing, complex receiver expressions, annotations on the assignment, multiline selector names, imported modules and arbitrary nested scopes are not claimed. Unit and browser tests cover actual compiler schemas, nested fields, optional exclusions and JS/PHP parity.

## Named signatures

Join the compiler's AST definition parameter names and selector labels with the checked schema by source location. Checked Mira transforms these into structured signature parts; the native CodeMirror adapter renders parameter names as semantic `em` elements, types upright, and selector labels distinct. The same representation is used for hover, Inspector and completion list. Legacy native libraries export parameter names from their actual AST and checked schemas where checking succeeds. Abstract service interfaces declare types but no parameter names: do not invent names for them. The full reference and local block scope remain separate work.

## Lexical assistance (initial)

An opt-in scope query reuses the actual checker LocalScheme map at a Name/literal source anchor; types are rendered after successful inference. No duplicate resolver in the editor. Mira combines local suggestions with unshadowed top-level names. For an incomplete identifier the editor can try a numeric placeholder in a temporary copy of the source; only names, not types, from that speculative check are displayed. The source is never modified by the probe. This is intentionally limited: a probe that cannot be parsed/checked yields no local information, headers, multiword cursor spans and arbitrary incomplete block structures are not supported. Global suggestions remain labeled with their provenance. Browser tests and direct checker tests cover lexical parameters, nested shadowing and declaration order. No LSP or general tolerant parser yet.

## Multifile workspace (first increment)

Pure checked Mira operations maintain the file list; JS implements the browser host and CodeMirror document states. Paths are relative `.mira` files, mapped to logical names using the same root-relative convention as the CLI. Each file has independent session undo history. The complete workspace autosaves to localStorage (not a durable external backup); JSON import/export and explicit native directory read/write are available. Chromium-compatible browsers with File System Access can open a folder and save the active file to real disk; permission is requested each session. Saves refuse detected external changes and do not delete files. No WebView dependency or Node server yet. Folder traversal skips hidden entries, node_modules and dist. Module path completion uses project files; imported symbols are derived from compiler-verified interfaces and dependency edges for direct selective/wildcard imports. Import declaration symbol completion, provider manifests, opaque-type field support and advanced module aliases require further work. No duplicate parser/resolver for import semantics. No automatic disk writes. A portable desktop host for Firefox/WebView remains planned.

Browser CI additionally creates two documents, verifies module-path completion, confirms direct imported signatures (private symbols excluded), and reloads to check both saved sources. Physical disk adapter tests use a test double; actual native file-picker permission UX still requires a manual browser check.

## Optional desktop host

Run `npm run studio:desktop -- <project-folder>` after building Studio and the IDE. Open the printed localhost URL in Firefox, Chrome or a future WebView. The Node standard-library host is bound to 127.0.0.1, serves only the built assets, and authorizes project reads/saves with a per-session random token in a request header. The selected root is fixed; path validation and symlink rejection limit writes, and saving checks expected on-disk text and uses a temporary file. No arbitrary command execution or CORS. Desktop mode uses explicit saves, not browser localStorage; unsaved buffers do not survive closing. This is a local prototype, not a sandbox against hostile concurrent local filesystem manipulation. No embedded WebView packaging yet.

## Windows portable distribution

CI packages the same verified Studio build and local desktop host with the official Windows x64 Node 22 runtime, checking the ZIP against the official SHA256 manifest. Bundled dependency licenses and Node license are included. `Avvia Mira Studio.cmd` opens a native folder picker (or accepts a dropped folder), then starts the browser via the default Windows association. No global runtime installation. Explicit disk saves via button or Ctrl+S, and a browser close warning for unsaved disk buffers. The Windows runner uses the packaged executable and launcher with `--no-browser`, drives Chromium through a real multi-file edit and import, restarts the host, and checks disk conflicts. The interactive folder picker/default browser launch still require manual verification. No WebView, installer, signed binary, or automatic update yet.

## Offline library catalog and runnable example copies

Build Studio's library index from the actual lib sources and the existing generated native API catalog; reuse existing JS host manifests and bindings, not a parallel library system. Project modules override built-in modules by logical path. Text, Date, the existing lesson-shaped JSON contract and Storage browser contracts are available for checked compilation; HTTP builds effect descriptors. The JS run worker supports pure result-producing examples and Text/Date/JSON, not general GUI, HTTP execution or persistent Storage operations (use the specialized labs). PHP emission selects the existing file Storage provider, but PHP execution is not bundled. Example opening creates a new .mira file in the current workspace without overwriting an existing file; save explicitly on desktop. Catalog and example source are cached with the IDE, and Windows includes original library/example/manifest source trees. Contextual links reuse existing reference routes; prose coverage is still incomplete. The first import-list completion supports native public symbols on the opening line; private symbols are not proposed. General import editing, custom provider manifests, project-specific JSON generation and execution of full-stack/GUI projects remain separate work.
